Papers and algorithms

The papers and the general techniques of geometry and computer science that zslice uses. zslice does not copy code from them. Each zslice file that uses a source names it in its header comment.

Smart guides

ideaui
Source
General
What zslice uses
A label snaps to the edges and centers of other labels, to holes, and to the center of the face or the part, and a part on the bed snaps to the other parts and the center of the bed, with guide lines.
License
General technique

The smart guides of drawing and design tools (for example Adobe Illustrator, Inkscape, and Figma): while an object moves, its edges and its center snap to the edges and centers of the objects near it and to equal gaps, and thin lines show each snap

License: General technique

Used in: src/label_snap.zig, web/app/label.js, linux/src/ui/label-tool.c, src/part_snap.zig, web/app/gizmo.js, linux/src/ui/view3d.c

How zslice uses it: A label that moves or changes size on a face snaps to the other labels of the face, to the round and square holes of the face, and to the center of the face and of the part. The code is new.

Early cutoff and verifying traces

paperslicing
Source
A. Mokhov, N. Mitchell, S. Peyton Jones
What zslice uses
A task runs again only if the hash of one of its inputs changed; the key of each level is a hash of the inputs of its plan.
License
Paper (facts and ideas only)
Link
https://doi.org/10.1145/3236774
Version
Proc. ACM Program. Lang. 2, ICFP, Article 79, 2018
Used in
src/form.zig, src/plate_job.zig

A. Mokhov, N. Mitchell, and S. Peyton Jones, "Build Systems a la Carte", ICFP 2018 (read on 2026-11-24). A build system with verifying traces records the hashes of the inputs of each task, and runs a task again only if one of them changed. With early cutoff, a task whose new result equals the old result stops the work after it.

License: Paper (facts and ideas only)

Used in: src/form.zig, src/plate_job.zig

How zslice uses it: The key of each level (PlateJob.levelKey) is a hash of all inputs of the plan of the level. A slice plans a level again only if its key changed. Two generations of the stream of each level keep the result of an undo.

Marching squares and the regions of many labels

paperslicing
Source
Lorensen and Cline, Wu and Sullivan
What zslice uses
The borders between the labels of a grid: a point on each grid edge between two labels, a straight piece in a cell with two labels, and pieces to the center of a cell with more labels.
License
Published methods
Used in
src/field.zig, src/paint_split.zig

William E. Lorensen and Harvey E. The regions of two labels then have no gap between them.

Distance fields: exact stamps, the chamfer distance, and the jump flood

paperslicing
Source
Borgefors, Rong and Tan, Hoff et al.
What zslice uses
The distance from each node of a grid to the nearest source: each source writes its exact distance to the nodes around it; a two-pass chamfer distance for a coarse test; the jump flood as the GPU form.
License
Published methods
Used in
src/field.zig

Gunilla Borgefors, "Distance transformations in digital images", Computer Vision, Graphics, and Image Processing 34 (1986): the two-pass chamfer distance. Kenneth E. Hoff III, Tim Culver, John Keyser, Ming Lin, and Dinesh Manocha, "Fast Computation of Generalized Voronoi Diagrams Using Graphics Hardware", SIGGRAPH 1999: each source draws its distance into a buffer, and the least value wins. Guodong Rong and Tiow-Seng Tan, "Jump Flooding in GPU with Applications to Voronoi Diagram and Distance Transform", I3D 2006: the same field in log n passes on a GPU

License: Published methods

Used in: src/field.zig

How zslice uses it: Field.stampSegment writes the exact distance of each source to the nodes within a radius, and each node keeps the least value (the method of Hoff et al., on the CPU, a vector of nodes a step). Field.chamfer is the two-pass distance of Borgefors, for the test "is paint near this core". The jump flood is the plan for the same field on a GPU; zslice has no code of it.

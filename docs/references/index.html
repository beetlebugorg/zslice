Code in the binaries

The zslice library, command line tool, and wasm module contain code from these projects. Their license texts are in licenses/.

Algorithms, formats, and conventions

These sources gave methods or formats. zslice does not copy their code. Each zslice file that uses a source names it in its header comment.

SourceLicenseUsed inHow zslice uses it
Clipper2, Angus Johnson. https://github.com/AngusJohnson/Clipper2Boost Software License 1.0src/offset.zigThe offset method: move each edge along its normal, join at the vertices (miter, round, or a loop through the original vertex at a closing corner), then a union with the "positive" fill rule. zslice has its own implementation.
Bala R. Vatti, "A generic solution to polygon clipping", Communications of the ACM 35(7), 1992Papersrc/clip.zigNamed as the sweep-line method that Clipper uses. zslice uses a different method (planar arrangement and winding numbers).
Winding numbers and fill rules (even-odd, non-zero, positive)General computational geometry; the names follow the SVG and PostScript fill rules and Clipper2src/clip.zig, src/offset.zigThe rule that decides if a point is inside a polygon set.
Shoelace formula for polygon areaMathematicssrc/geom.zigThe signed area of a polygon.
John Amanatides and Andrew Woo, "A Fast Voxel Traversal Algorithm for Ray Tracing", Eurographics 1987Papersrc/clip.zigThe walk of an edge through the cells of the uniform grid that finds candidate crossings.
Doubly connected edge list (half-edge structure), as in de Berg et al., "Computational Geometry: Algorithms and Applications"Textbook methodsrc/clip.zigThe faces of the arrangement, walked to find the winding numbers.

TOML v1.0.0, https://toml.io/en/v1.0.0MIT (the specification)src/toml.zig, src/profile.zigThe profile file format. zslice parses a subset.
OctoPrint REST API, https://docs.octoprint.org/en/master/api/ (/api/printer, /api/printerprofiles, /api/job, /api/files/local, the X-Api-Key header)AGPL-3.0 (OctoPrint; the API, not code)linux/src/net/printer-link.cRead the state of a printer, and send G-code to it. printdeck has the same API.
Moonraker API, https://moonraker.readthedocs.io/ (/printer/objects/query, /server/files/upload)GPL-3.0 (Moonraker; the API, not code)linux/src/net/printer-link.cThe same, for Klipper printers.

G-code over a serial port: one command, then wait for the line ok (the Marlin and RepRap host protocol), https://reprap.org/wiki/G-codeProtocollinux/src/net/printer-link.cThe USB connection.
Tree support: the idea of branches that hold overhangs at points and join on the way down, as in Cura "tree support" (LGPL-3.0/AGPL-3.0) and PrusaSlicer "organic support" (AGPL-3.0)Idea; no codesrc/tree_support.zigzslice has its own method: tips on a fixed grid, moves limited by the branch angle, joins of nodes that touch, and a radius that gets smaller in narrow spaces.
Lightning infill, Ultimaker Cura 4.12 (December 2021), https://github.com/Ultimaker/Cura/releases/tag/4.12.0, implemented in CuraEngine (https://github.com/Ultimaker/CuraEngine)AGPL-3.0 (CuraEngine); the method only, no code copiedsrc/lightning.zigThe idea of the pattern: branches only under the top surfaces, grown from the top down, joined into trees that end at the walls, and shortened on each layer down by an angle. zslice has its own method and code (see the file header).
Thibault Tricard, Frédéric Claux, and Sylvain Lefebvre, "Ribbed Support Vaults for 3D Printing of Hollowed Objects", Computer Graphics Forum 39(1), 2020, https://diglib.eg.org/handle/10.1111/cgf13750Papersrc/lightning.zigThe method that the Cura lightning infill comes from: walls under the surfaces of a hollow object that get smaller and straighter on the way down, and merge into the walls of the object.
Juraj Vanek, Jorge A. Integer coordinates in micrometers, as in CuraEngine (https://github.com/Ultimaker/CuraEngine)AGPL-3.0src/geom.zigThe coordinate unit. CuraEngine uses 1 unit = 1 micrometer (include/types/Coord_t.h). zslice uses the same unit. No code is copied.

The gyroid, a triply periodic minimal surface (Alan Schoen, 1970), with the common approximation sin x cos y + sin y cos z + sin z cos x = 0. The Slic3r flow model: the cross section of an extruded bead is a rectangle with half circles on the sides (Slic3r and PrusaSlicer, Flow.cpp, and the Slic3r manual)AGPL-3.0 (the model, not code)src/flow.zigThe plastic volume for each line, and the bead width in the 3D view.
Scanline polygon fill (sort the edge crossings on each line, fill between them by winding number)General computer graphics techniquesrc/infill.zigThe line infill.
Combined infill: sparse infill printed once every n layers, as one taller bead. PrusaSlicer "Combine infill every n layers" (infill_every_layers, https://github.com/prusa3d/PrusaSlicer, from Slic3r) and Cura "Infill Layer Thickness" (infill_sparse_thickness, https://github.com/Ultimaker/CuraEngine) have it. Slic3r and PrusaSlicer limit the combined thickness to the nozzle diameterAGPL-3.0 (the idea and the limit, not code)src/layer.zig, src/engine.zigproject.infill_layers. zslice has its own method: groups from the bottom skin up, the area that is sparse in all layers of a group (with no band under a top), a bead of the group height from the flow model. No code was read or copied.
Cura project 3MF files (Ultimaker Cura, https://github.com/Ultimaker/Cura, plugins/3MFReader and plugins/3MFWriter): the per-object settings in <metadata name="cura:..."> entries of each object, in the namespace http://software.ultimaker.com/xml/cura/3mf/2015/10, the modifier volume flags (infill_mesh, cutting_mesh, anti_overhang_mesh, support_mesh), infill_mesh_order, and the setting names in fdmprinter.def.jsonLGPL-3.0 (Cura; the format and the names, not code)src/threemf.zig, src/import_cura.zig, src/part_settings.zigThe reader keeps the metadata of each object. Infill meshes ("Modify settings for infill of other models") and infill_mesh_order in CuraEngine (https://github.com/Ultimaker/CuraEngine, FffPolygonGenerator::processInfillMesh): the volume does not print; inside it, the infill of the other meshes gets the settings of the volume, and the mesh with the higher order wins an overlapAGPL-3.0 (the behavior, not code)src/layer.zig, src/engine.zig, src/part_settings.zigThe modifier volumes of zslice (layer.Modifier). zslice has its own method: the area of a volume on each layer, cut from the sparse area (and the skin area, if the volume has no top and no bottom thickness) of the part. No code was copied.
The trihexagon infill pattern of CuraEngine (Infill::generateTrihexagonInfill: three line sets at 0, 60, and 120 degrees, the third moved by half the line distance), the infill line distance of each pattern (infill_line_distance: line width / density times 2 for grid, 3 for triangles, trihexagon, and cubic), and the list of infill angles (infill_angles, one angle for each layer in turn; Cura measures the angle from the Y axis)AGPL-3.0 (the patterns and the conventions, not code)src/layer.zig, src/import_cura.zig, src/settings.ziginfill_pattern = trihexagon, the density from infill_line_distance, and project.infill_angles.

The npm package

The package @beetlebugorg/zslice is on GitHub Packages (not npmjs.com). It has the web app (app/), this API (zslice.mjs), and a Node command, zslice slice, that slices a model to G-code with profiles. Each version tag publishes it (.github/workflows/npm.yml). It also has the G-code viewer (view/, see The G-code viewer). See its README for the install: GitHub Packages needs a token, also to install.

npm install @beetlebugorg/zslice
npx zslice slice part.stl -m printer.toml -p fine -o part.gcode

To serve the web app from your own server (for example a printer on the LAN), serve node_modules/@beetlebugorg/zslice/app/. It uses only relative URLs. Send Cross-Origin-Opener-Policy: same-origin and Cross-Origin-Embedder-Policy: require-corp for the threads.

To build the package from the source: zig build web && python3 -I tools/npm_package.py, then zig-out/npm.

Build

zig build wasm

This makes zig-out/web/zslice.wasm (about 5.8 MB, 1.7 MB with gzip) and zig-out/web/zslice.mjs (the wrapper).

The module has two imports, env.zs_web_event and env.zs_web_set_event: the events of the app core (see The app core in a browser). zslice.mjs gives an empty function for each. If you instantiate the module yourself, give them too:

const { instance } = await WebAssembly.instantiate(wasmBytes, { env: { zs_web_event() {}, zs_web_set_event() {} } });

Use

import { load, ZsliceError } from "./zslice.mjs";

const wasmBytes = await (await fetch("zslice.wasm")).arrayBuffer();
const zslice = await load(wasmBytes);

const stlBytes = new Uint8Array(await file.arrayBuffer());
try {
  const { gcode, stats } = zslice.sliceStl(stlBytes, {
    "project.layer_height": 0.15,
    "project.wall_count": 3,
    "filament.nozzle_temp": 220,
  });
  console.log(`${stats.layerCount} layers, ${(stats.filamentMm / 1000).toFixed(2)} m`);
} catch (e) {
  if (e instanceof ZsliceError) console.error(e.message, e.status);
  else throw e;
}

The wrapper API

load(wasmBytes) returns an object with:

MemberWhat it is
versionThe version text.
settingNamesAn array of all setting names.
sliceStl(stlBytes, settings)Slices an STL file. stlBytes is a Uint8Array or an ArrayBuffer. settings is an object of "group.name": value. Returns { gcode, stats }.

stats has layerCount, retractions, filamentMm, filamentG, printTimeS, and travelMm.

On a failure, sliceStl throws a ZsliceError. Its status field is the C status code (see the overview).

Run it in a Web Worker

The wasm module has no threads, and a slice blocks the thread that runs it. In a browser, run it in a Web Worker:

// worker.mjs
import { load } from "./zslice.mjs";
const zslice = await load(await (await fetch("zslice.wasm")).arrayBuffer());
self.onmessage = (e) => {
  try {
    self.postMessage(zslice.sliceStl(e.data.stl, e.data.settings));
  } catch (err) {
    self.postMessage({ error: err.message, status: err.status });
  }
};
// page.js
const worker = new Worker("worker.mjs", { type: "module" });
worker.onmessage = (e) => console.log(e.data);
worker.postMessage({ stl: stlBytes, settings: { "project.wall_count": 3 } }, [stlBytes.buffer]);

Node.js

web/test.mjs is a working example for Node.js:

node web/test.mjs zig-out/web/zslice.wasm part.stl

The app core in a browser

The module also exports the app core and the 3D view of include/zslice-app.h. The web app (web/app/, see its README) uses them:

  • zs_app_new_web makes an app whose events go to the import env.zs_web_event(event, progress, status). A slice runs on the calling thread, so run the app in a Web Worker.
  • zs_set_new_web makes a plate set (one app for each plate) whose events go to the import env.zs_web_set_event(plate, event, progress, status). Call zs_set_step from a timer: each call slices the next waiting plate, the active plate first.
  • zs_view_new with ZS_SURFACE_WEB (3) makes a 3D view with no GPU in the core. After zs_view_draw, zs_view_web_frame gives the frame data in wasm memory, and the page draws it with WebGL2 (see web/app/gl.js).
  • zs_view_scene_write and zs_view_scene_read move the loaded scene from the view of one wasm instance (the worker) to the view of another (the main thread). For a large scene, zs_view_scene_stage reads it in steps of a byte budget (one step for each frame), and zs_view_scene_commit then swaps it in at once; until then the view draws its old scene. zs_view_scene_span gives the place of the instances and of the light beads in the bytes, so the page can send them to the GPU in steps before the commit.
  • A set of plates has one app for each plate. zs_view_set_plates puts the plates in a row in one view, and zs_view_plate_scene_read gives the view the beads of a plate that is not the active plate. With a zs_set in the worker, zs_set_sync_write writes all of these changes as bytes, and zs_view_sync_read applies them to the view of the page. zs_app_trim frees the memory of an app that waits (the memos of its last slice), and keeps its result.

Memory

The wasm memory grows while a slice runs, and it does not shrink. To free all memory, drop the module object and load it again.

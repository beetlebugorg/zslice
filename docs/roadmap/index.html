Milestone 1: the core, from end to end

  • Integer geometry and a flat polygon store
  • Polygon booleans (planar arrangement and winding numbers)
  • Polygon offset
  • STL load (binary and ASCII) with vertex welding
  • Mesh slicing with chain repair for open meshes
  • Settings in three parts: machine, filament, and project
  • Line infill (scanline)
  • Layer plan: walls, top and bottom skin, sparse infill, path order
  • G-code output
  • Engine: two passes, multi-thread, batched output for low memory
  • C API, wasm build, and a JS wrapper
  • Command line tool with an SVG layer preview
  • Documentation: user guide, embedding guides (Zig, C, JS), internals (pipeline, architecture, contributing)
  • Corpus test: all STL files tracked in printdeck slice with no error

Milestone 2

  • Support structures, for overhangs and bridges.
  • Ironing on top surfaces (project.ironing).
  • Profiles. Machine, filament, and project profiles are separate files. Load order: machine, then filament, then project, then overrides. An override can change any field, for example filament.nozzle_temp=230 for one project. Later: overrides for each object in a project.
  • Profile format: TOML (a subset: comments, key = value, strings, numbers, booleans, multi-line strings), with a small parser in zslice. extends = "name" loads a base profile first. Example: a brand PLA profile, and a gray PLA profile that extends it and changes one value.
  • Profile importers. Read Cura profiles (and other slicers) and convert them into zslice machine, filament, and project profiles. The printdeck TAZ profile (printdeck/profiles/taz-workhorse-se) is the first test case.
  • 3MF load.

Done in November 2026

  • The web app on WebAssembly (zslice.beetlebug.org): the same window as the GTK app, the 2D view, the Selected page, the context menu, a resizable panel, and the plate kept across a refresh
  • Printer onboarding: a library of 1181 printers from Cura, Cura LulzBot Edition, PrusaSlicer, and OrcaSlicer, a picker with search, network search (printdeck, OctoPrint, Moonraker, PrusaLink), and the bed model of 830 printers in the 3D view
  • A history of changes: a timeline with a badge for each kind of change, a History tab, a click goes back to a change, a double click edits it, undo of one change, and marks on the layer slider for the changes of some layers
  • Tools: Select, Move, and Measure; a measure tape that snaps to the ends of the lines and to the centers of circles; the measurements of a selected line (segment, edge, path, radius)
  • Retractless top and bottom skin: the pieces of the skin join into few paths along the walls
  • Gap fill, and bridges for skin and for walls
  • Smart placement that counts the islands of an orientation (a part on a 45 degree edge)
  • Infill ribs: a line in each narrow infill area that a sparse infill misses
  • A Cura-like camera: a left or right drag orbits with the bed level; a touchpad pans with two fingers and zooms with a pinch
  • A privacy page: no analytics, no cookies, nothing loaded from other sites

Feature parity with PrusaSlicer and Cura

The goal is the features that people use in PrusaSlicer and Cura. zslice designs each one again, and does not copy their code or always their method. The order is by how often a print needs the feature.

Print quality and strength

  • Walls, top and bottom skin, sparse infill (lines, grid)
  • Ironing
  • Support: grid support with interface layers, XY and Z gaps, everywhere or bed only
  • Support: tree support, support blockers and enforcers (marks in the 3D view), bridges without support (support_style bridge)
  • Skirt and brim
  • Bridges: find them, print them with their own direction, speed, flow, and fan
  • Overhang walls: slower speed and more fan for overhang
  • Seam placement: sharpest corner (hidden), rear, nearest, random
  • Gap fill and thin walls with a variable line width: Arachne walls, ported from CuraEngine (project.wall_generator = arachne)
  • Infill patterns: gyroid, cubic, triangles, concentric
  • Infill patterns: honeycomb, adaptive cubic
  • Infill patterns: lightning
  • Top and bottom patterns: monotonic, concentric
  • Infill only where needed, and denser infill under top surfaces
  • Wall order (inner first or outer first) and extra walls on alternate layers
  • Fuzzy skin
  • Spiral vase mode
  • Variable layer height (adaptive and by hand)
  • Size compensation: XY offset, hole offset, elephant foot, shrinkage
  • Polyholes

Motion and extrusion

  • Avoid crossing walls (combing) on travel
  • Retraction on layer change, z hop only for a travel that crosses an edge
  • Wipe on retraction: a small swirl toward the inside of the part while it retracts, as a person wipes a drip
  • Coasting
  • Acceleration and jerk control for each feature; a time estimate with acceleration
  • Arc fitting (G2/G3)
  • Pressure advance and input shaper calibration prints
  • Cooling: minimum layer time, fan boost on short layers, slow down for small layers
  • Firmware flavors: Marlin, Klipper, RepRapFirmware, Bambu, with exclude-object labels

Models and plate

  • More than one object on the plate, with automatic arrangement
  • 3MF load (parts at their places, components, units, zip64; items that overlap stay one part) and 3MF plate save (Ctrl+S)
  • OBJ and STEP load
  • Rotate, scale, place on face ("Put this side on the bed")
  • Mirror, cut
  • Modifiers (per-region settings), and settings for each object
  • Mesh repair
  • Sequential printing (one object at a time)
  • Multi-material and more than one tool head: a filament (and color) for each part or region, tool changes with the start and end G-code of each tool, a wipe tower, an ooze shield, painted regions (the library has dual-extruder printers)
  • Sliced layer preview in 3D, with speed, flow, and feature views

Profiles and workflow

  • Machine, filament, and project profiles in TOML, with extends and overrides (command line)
  • The app keeps its settings after a restart (~/.config/zslice/{machine,filament,project}.toml, only the changes from the defaults)
  • Profiles in the app: pick, edit, and save profiles, through the C API with a resolver callback
  • Import of Cura profile stacks (the printdeck layout with cura.json)
  • Import of PrusaSlicer and OrcaSlicer profiles, and of a Cura profile export (.curaprofile)
  • Shrinkage compensation and XY offsets for outlines, holes, and the first layer (imported from the printdeck rolls)
  • A printer profile library
  • Send to printer: printdeck, OctoPrint, Moonraker (native; the web app since 0.1.0-beta, and printer.json for a printer that serves the app)
  • Calibration prints: temperature tower, flow, retraction, pressure advance

App

  • App core (src/app.zig, include/zslice-app.h): model, settings with descriptions, background slice with progress and cancel, layer paths for the preview, G-code export, license list
  • Linux shell: GTK4 (linux/): open (button, drop, command line), settings panel from core data, slice after each change, layer preview with zoom and pan, export, licenses
  • 3D view of the toolpaths: Vulkan renderer in the core, Wayland subsurface in the GTK shell
  • 3D view: beads with the real cross section and round ends, the deposited width, the cooled size, the filament color with PLA-like light, 4x MSAA
  • 3D view: CAD mouse (orbit, pan, free rotation, zoom to the pointer), smooth zoom and reset, no tilt limit
  • 3D view: X11, the model mesh before the slice, a level of detail for beads smaller than a pixel
  • 3D view, physics not modeled yet: the seam blob, sag on overhangs and bridges, stringing, corner rounding by acceleration
  • Click a path in the 2D or 3D view to inspect it: its real values with the reasons, and the settings that change it, editable in place
  • Replay: play the print in the 3D view, line by line, at 1x, 2x, 3x, 10x, 30x, 100x, from the move times of the G-code
  • Live settings: a value goes to the core after a pause in the typing; Up, Down, and a drag on the label step it; units on each value, ratios as percentages; all editors of a setting stay in sync
  • A stable UI during a new slice: the inspector updates in place, the tab stays, the status bar keeps its size and dims the old numbers
  • Settings browser in columns: sections, then settings, then the help and the lines of the project that the setting changes, highlighted in the preview, with their share of the print time; search; defaults with reset
  • Realtime sliders: drag a value (infill density, speeds) and see the slice change as fast as the slicer can go (the layer regions stay between slices; the shell queues values instead of a restart)
  • Usual ranges (sliders, a warning out of them) and hard limits (an error) for the number settings
  • Focus: the lines that a setting changes are solid, and the other lines are ghosts that do not hide them
  • Each setting shows in the preview: lines, or marks (seam blobs, travel moves, retractions), or a note (a test checks it); a section shows the lines of all its settings
  • The selection stays on the same kind of line when a new slice moves it (a new skirt distance)
  • The preview controls and a thin layer slider float over the view
  • Slider steps that people use (0.01 mm for a layer height, 5 degrees for a temperature), with a tick at the default
  • Faster skin regions: a sliding window for the stacked intersection, then SIMD in the boolean
  • Machine origin: the G-code position of the front left bed corner (center origin printers, Cura machine_center_is_zero)
  • Top and bottom skin patterns: lines, monotonic, concentric; the skin angle and its turn per layer
  • Changes for the part (inline): for all its layers, or for some layers (overrides by z range); the Settings page has the defaults for all prints
  • 3MF: save the parts with their changes and overrides; with more than one STL, one new 3MF with all of them
  • 3MF: changes for each part (now the changes are for the whole plate)
  • Preferences window: printers (more than one, each with its machine settings), connections (printdeck, OctoPrint, Moonraker, USB serial), a connection test that reads the bed, the nozzle, and the filament of the printer, global app settings (theme, first view, threads)
  • Send to the printer (upload, or upload and print), and the state of the printer in the status bar
  • Seam mode "hidden" (the default): the most hidden point (inside corners over about 1 mm, the back, not over air; ties to the back, so the seams line up)
  • More infill: honeycomb; zigzag (lines joined at the walls, no travel between them); flow (zigzag, twice as dense in a band under the top surfaces)
  • More infill: adaptive cubic; make flow cheaper (the band costs a stacked intersection on the first slice, and memory in the cache)
  • Skin expand distance, skin removal width, and solid infill for narrow sparse areas (no gaps between the top skin and the walls)
  • Thin walls: a loop with a narrower line in each part thinner than one line width
  • Thin walls with a variable line width along the part (project.wall_generator = arachne)
  • Arachne walls as the default wall generator, after test prints
  • Tree support (support_style = tree): tips on a grid under pads, branches that join and get thicker, thinner in narrow spaces (deep holes)
  • Tree support: faster (1.4 s on the camera arm, grid 0.4 s), branch routing around the part toward the bed, a preview of the branch nodes
  • Layer times: in the layer slider (with a mark for a layer that min_layer_time slows down), and a color mode by layer time
  • A cooling lap (filament.cooling_mode = lap): a short layer prints at full speed, then the head moves 1 mm over it with the fan at full until the min layer time
  • The cooling lap in the preview and the replay (its moves are not in the toolpaths yet)
  • printdeck web module: the core in wasm, a WebGPU backend for the 3D view, the slicer in the printdeck web UI and cloud
  • Combing: travel inside the part over the infill and the inner walls, with no retraction, and faster
  • Preview color modes in 3D: filament, feature, speed, flow, layer time, line width, with the range of the ramp
  • Color modes in the 2D view, and a layer height mode (with variable layer heights)
  • Ironing in the preview: the ironed top skin looks flat; the inspector shows what ironing costs in time
  • Plate: more than one part (open or drop many STLs), Shift+click to select a part, Shift+drag to move it, Shift+wheel to turn it, a part page, and "Arrange the plate" (rows, the largest first)
  • Plate: a best placement that turns each part for less support, and lay flat
  • Printer library: 1080 printers of 187 brands from Cura, PrusaSlicer, and OrcaSlicer (tools/printer_library.py, src/printers.zig); the printer picker with search, brands, a drawing of the build volume, and the key facts, at the first start and from the printer menu (GTK and web)
  • Printers on the network: mDNS for OctoPrint, printdeck, Moonraker, and PrusaLink (src/discovery.zig), the kind from /api/version, the bed from Klipper
  • Printer library: the start G-code of the definitions with scripts ({if}, expressions: about 40 % of the models get the zslice start G-code now), more than one extruder, the bed shape of round beds in the plate and the 3D view, the heated bed and chamber in the G-code
  • Printer discovery: Bambu Lab in LAN mode (SSDP), Elegoo (SDCP), Creality, and Duet; the model of a printdeck or OctoPrint printer (it needs the API key)
  • Printers: a shared place for printers and their connections (printdeck remote, OctoPrint, Moonraker), and print monitoring
  • Replay: a nozzle marker, and the time estimate with acceleration (the replay is as exact as the time estimate)
  • Projects from GitHub in the web app: open a repo or a folder with a printdeck.yml, choose the parts, slice each plate with its Cura profile stack, and keep the status of each plate across a reload
  • Projects in the desktop app
  • Debug prints: "Print this layer" (one layer alone on the bed), and a range of about 10 layers laid flat side by side, to compare a print with the preview
  • Check the G-code of each printer of the library: slice a test part with each profile and test the start and end G-code

Performance

  • The polygon boolean was O(n^2) for long edges. It now finds crossings with a grid and winding numbers by a walk over the faces.
  • The support column pass (support.zig step 2) runs on one thread. The slowest corpus file with support takes 11 s on 2 threads. Split the layers into bands that run in parallel, or use a coarser area for the carry.
  • Clip open lines (infill, ironing) with a direct method, not with the scanline of a region.
  • Pass one scratch arena for each layer to the boolean and offset calls.

Ideas to test

  • Zigzag walls. Replace the inner walls with one path that goes back and forth across the wall band, around the part. The goal is a stronger wall. The outer wall stays a loop for a good surface. Test: print test bars with loop walls and with zigzag walls, and break them.
  • Speed from limits. The project sets a speed ratio for each feature, and the engine computes the speed from the limits of the machine and the filament. This is in milestone 1. Next: add the acceleration limits.
